Tab closing
test cases

Check the two closing preferences, then work through ordinary tabs, split views, pinned tabs, groups and bookmarks. Each case specifies a starting state, actions and expected survivors. Layouts, languages and input variants have separate results.

This is a test checklist, not a completed test report. Every result starts as Not run. Test the features available in your installed version and explain any Blocked or Skipped result.

Before testing

  1. Use a Phi Browser version that offers Double-click to close tabs and Close tabs by position in Settings → Advanced. Record the app version from About Phi and the device you are testing.
  2. Create a disposable TC-QA Space and use the test pages below. Pins can be shared between Spaces. Leave personal pages, drafts and saved entries outside the test. Change only test items you create.
  3. Record your original layout, both switches and any shortcut you temporarily change. Recreate the specified tab sequence before each case and wait for titles and order to settle.
  4. For an unsaved-changes page, type disposable text and wait for Leave confirmation enabled before testing a close. Compare the marker and opening ID to distinguish a retained original page from one that was closed and reopened.
  5. Keep the checklist in a separate window so a batch close cannot remove your run notes. Results stay in this browser on this site; export them before switching devices or clearing site data. Do not enter personal information in test pages or notes.

Coverage and priorities

P0 checks core behavior and data protection. P1 covers the full regression set. P2 covers optional environments and exploratory behavior. A skipped, blocked or untested case is never a pass. For exploratory cases, record observations if an acceptance detail is unspecified.

Prepare test objects

Ordinary tabs and markers

Open the generated A–F links one at a time. Arrange the actual tab order, enter a different disposable marker in every page that should survive, and note its opening ID. Use the same batch ID throughout one setup.

Ordinary and grouped split views

Use the app's existing Open as Split action to pair B/C. Verify both titles and pane contents before testing. For a grouped split, create a disposable TC-G group and move the split into it. Check membership, orientation and size ratio before each operation.

Pins and pinned splits

Pin only a generated test page or split. Mark both panes separately. To test closed saved entries, explicitly close their live pages while leaving the saved pins. Afterward unpin only entries you created for this run.

Groups and collapsed groups

Create a named TC-G group using disposable pages B/C/D, set a recognizable color and record membership. Use the heading's disclosure control to collapse it. Distinguish a heading menu from a member menu. Recheck the group name in any deletion prompt.

Bookmarks and folders

Save generated M and, where supported, split MS[M+N] inside a test folder. Open saved entries through their bookmark controls in vertical layouts. To create an ordinary copy, copy its URL and open it separately in a new tab. Check the actual UI category before deciding whether it is protected.

Unsaved changes, media and downloads

Select Unsaved changes confirmation in the generator, open the page and type disposable text. Its status must say Leave confirmation enabled. Audio starts only after you choose Start test tone. The small text download tests the download UI, but cannot establish coverage of a long-running download or its close confirmation.

Report and clean up

  1. Complete all applicable P0 checks and the planned P1 regression set. Explain missing environments, P2 observations and every Failed, Blocked or Skipped result.
  2. For a failure, include the case ID, layout, app version, switch values, starting order, active page, clicked anchor, action, expected/actual survivors and dialog choices. Remove personal URLs and account details from screenshots or crash reports before sharing.
  3. Export JSON and Markdown. Exports include every execution point, including results hidden by filters. A failed, blocked or skipped case without notes is highlighted for follow-up.
  4. Restore your original layout, preferences and shortcuts. Unpin only test-created entries and remove only disposable test groups, bookmarks and windows after checking each one.

This site has no analytics or result-upload service. Run notes are stored locally in your browser. Test-page drafts are temporary and are not saved by this site. Share a report only when you choose to do so.
